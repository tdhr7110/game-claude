# 図鑑アイコン画像 制作規格 (TEST15)

TEST11で確定した自由合体レイヤー素材(`public/assets/chimera-layers/`)の規格をベースに、
図鑑(部位・敵)のアイコン画像向けに定めた規格です。レイヤー合成用の素材とは用途が異なる
（図鑑は「1体を代表する1枚絵」、レイヤー素材は「パーツごとに重ねる部品」）ため、
ディレクトリ・マニフェストは分離しています。

## ファイル配置規約(手入力の分岐を増やさないための唯一のルール)

- 部位: `public/assets/collection-art/parts/<partId>.png`
- 敵: `public/assets/collection-art/enemies/<enemyId>.png`
- 未発見時の共通シルエット: `public/assets/collection-art/_silhouette.png`

**ファイル名は必ず `<id>.png`（part.ts / enemyCatalog.ts のidそのまま）にすること。**
コード側は `id → ファイル名` をこの命名規則だけで解決し、`if (id === 'xxx') return 'yyy.png'`
のようなID別の分岐は一切書きません(`src/ui/collectionArt.ts` 参照)。新しい画像を追加する場合は
正しい名前のPNGをこのディレクトリへ置くだけでよく、コード変更は不要です。

## 画像規格

| 項目 | 規格 |
|---|---|
| フォーマット | PNG, 8-bit RGBA (アルファチャンネル必須) |
| キャンバスサイズ | 256 × 256 px 固定 (TEST11のレイヤー素材と同一) |
| 背景 | 完全透過 (背景色を敷かない。四隅は alpha=0) |
| 余白(マージン) | 図柄の不透明領域は中央240×240pxの安全領域内に収める(外周8px以上を空ける) |
| 向き・構図 | 図柄は正方形キャンバスに対して極端に偏らせず、中心から水平方向に大きくずれない位置に配置する(自動検査ではバウンディングボックスの中心オフセットで代用チェック) |
| 色 | 対応する部位/敵の `color` フィールドを基調色として使う(図鑑上で一貫した配色にするため) |

## 開発フロー

1. `public/assets/collection-art/parts/` または `enemies/` へ、上記規格を満たすPNGを置く。
2. `npm run art:scan` でマニフェスト(`src/data/collectionArtManifest.generated.ts`)を再生成する。
   - 未登録(絵が無いID)・未使用(IDに対応しない余分なファイル)・規格違反・重複割り当てをレポートする。
3. `npm run art:check` はビルド前チェック用(規格違反があると非ゼロ終了)。
4. アプリ側は `src/ui/collectionArt.ts` の `getPartArtUrl` / `getEnemyArtUrl` を使う。
   画像が無い/規格違反で除外された場合は自動的に `null` を返し、UI側は既存のアイコン絵文字表示へ
   フォールバックする(欠損時の見た目が壊れることはない)。

## この段階(TEST15)のスコープ

全部位・全敵の画像を一度に量産せず、カテゴリ(昆虫・ゴーレム・ドラゴン・特殊/種族なし)ごとに
代表部位を数点、敵は通常/強敵/ボスから1体ずつ実装し、制作規格とゲーム内表示(図鑑・未発見シル
エット・欠損フォールバック)の確定を優先しています。未実装分は図鑑の「未登録画像」開発者パネル
(デバッグパネル内)に一覧表示されます。
