# キメラバトル（プロトタイプ）

倒したモンスターから部位を奪い、自分の身体へ自由に装着して強くなる、ダークファンタジー調の
短時間オートバトル・ローグライトのプロトタイプです。戦闘は完全自動。プレイヤーは部位の取得・
装着・取り外しでビルドを組み、全8戦のランを駆け抜けます。

画像・アニメーション類は一切使用せず、図形・絵文字・テキストのみでゲームシステムの成立を
検証するための MVP（実験的プロトタイプ）です。

## 起動方法

Node.js（推奨: v18以上）と npm が必要です。

```bash
npm install
npm run dev
```

コンソールに表示される URL（既定では `http://localhost:5173`）をブラウザで開いてください。

その他のコマンド:

```bash
npm run build    # 型チェック + 本番ビルド（dist/ に出力）
npm run preview  # ビルド結果をローカルで確認
npm run lint     # oxlint による静的解析
npx tsx scripts/simulate.ts   # バランス検証用の自動シミュレーション（後述）
```

## 使用した技術

- React 19 + TypeScript
- Vite 8（ビルド・開発サーバー）
- 外部UIライブラリ・状態管理ライブラリは不使用（React標準の Context + `useReducer` のみ）
- 画像素材・音声は不使用。表示は絵文字・CSSグラデーション・テキストのみ
- バックエンド・通信・セーブ機能なし（すべてブラウザのメモリ上で完結）

## ファイル構成

ゲームデータ・戦闘/進行ロジック・UI（React）の3層に分離しています。

```
src/
  data/                 # ゲームデータ定義（値のみ。ロジックを持たない）
    types.ts            # 部位・敵・シナジーなどの型定義
    parts.ts             # 部位データ（28種: 24種族部位 + 特殊部位4種 + 初期の弱い腕）
    enemies.ts           # 敵データ（通常6種・強敵3種・中ボス生成・最終ボス）+ 敵スケーリング
    synergies.ts         # 部位数シナジー / 種族シナジーのテーブル

  engine/                # ゲームロジック（React に依存しない純粋なTS）
    capacity.ts           # 接続容量・実効接続コストの計算
    synergyEngine.ts       # 装着部位からシナジー発動状況を算出
    modifiers.ts            # 部位効果+シナジーから戦闘用の修飾値(CombatantModifiers)を合成
    battle.ts                # リアルタイム自動戦闘エンジン（tick駆動、ダメージ計算、状態異常、
                              # コンボ発動、ログ生成、速度変更、デバッグ用フック）
    run.ts                    # 1ラン全体の進行管理（8戦構成、装着/取り外し、ドロップ生成、
                              # 勝敗判定、デバッグ操作）純粋な状態遷移関数群

  ui/
    GameContext.tsx        # useReducer による状態管理をReactへ橋渡し（Action定義含む）
    format.ts               # 表示用のラベル・色・アイコンのマッピング
    components/
      PrepScreen.tsx         # 戦闘準備・部位管理画面
      BattleScreen.tsx        # 戦闘画面（自動戦闘のtickループを所有）
      DropScreen.tsx           # 部位ドロップ選択画面
      ResultScreen.tsx          # 勝利/敗北結果画面
      DebugPanel.tsx             # デバッグパネル（右ドロワー、折りたたみ可能）
      PartCard.tsx / PartDetailPanel.tsx / SynergyPanel.tsx / CapacityBar.tsx
                                  # 共通UI部品

  App.tsx                  # フェーズ(prep/battle/drop/result)に応じた画面切り替え
  index.css                 # 全スタイル（ダークファンタジー調のテーマ）

scripts/
  simulate.ts               # ヘッドレスでランを多数回自動シミュレートし、
                              # 各戦闘の所要時間・勝率を集計するバランス検証スクリプト
                              # （本番ビルドには含まれません）
```

新しい部位・敵・シナジーを追加する場合は、`src/data/*.ts` に定義を1件追加するだけで
自動的にゲーム内（ドロップ候補・デバッグパネルの部位選択など）に反映されます。

## 実装した機能

- **完全自動戦闘**: プレイヤー・敵それぞれの装着部位/攻撃パターンが独立した攻撃間隔で動作。
  一時停止・1倍・2倍・4倍のゲーム速度切り替えに対応。
- **自由装着システム**: 固定装備枠なし。同じ部位種類・同じ部位を何個でも装着可能
  （腕6本以上、脚8本以上などの極端なビルドが成立）。接続容量の範囲内でのみ装着可。
- **部位データ**: ID・名前・部位種類（腕/頭/心臓/脚/皮膚）・種族（昆虫/ゴーレム/ドラゴン/無属性）・
  レアリティ（コモン/アンコモン/レア）・接続コスト・HP補正・攻撃力・攻撃間隔・能力タグ・
  パッシブ効果・色/アイコンを持つ。
- **部位数シナジー**（腕4/6/10、頭3/5、心臓3/5、脚4/8、皮膚3/5）と
  **種族シナジー**（昆虫/ゴーレム/ドラゴン 各3部位・6部位）を実装。
  発動中のシナジーと次の閾値までの必要数をUIに表示。
- **状態異常**: 毒（一定間隔でダメージ→数値-1、種族シナジーで減少防止）、
  炎上（固定ダメージ・時間経過で消滅・重複でダメージ/時間が増加）。プレイヤー・敵の両方に適用可能。
- **接続容量を増減する特殊部位**: 巨大肉塊・増殖細胞・多腕核・百足の心臓を実装し、
  接続コスト軽減や容量拡張による極端なビルドを実際に成立させています。
- **ドロップ・ラン進行**: 敵を倒すと種族に対応した部位候補3つを提示（中ボス/最終ボスは
  高レアリティ寄りの抽選）。装着 or インベントリ保管を選択可能。全8戦（通常/通常/強敵/通常/
  中ボス/通常/強敵/最終ボス）を経て勝敗判定、最終ビルド表示、新しいラン開始が可能。
- **デバッグパネル**: 任意の部位付与、接続容量の増減、HP全回復、敵の即時撃破、速度変更、
  次の戦闘へ進む、ランのリセット、戦闘計算ログの詳細表示切り替えに対応。右側ドロワー形式で
  折りたたみ可能（本文をpaddingで押しのけるため、他のボタンと重なりません）。

## 動作確認した内容

- `npm run build`（`tsc -b` の型チェック含む）が警告・エラーなしで通ること。
- `npm run lint`（oxlint）でエラーが出ないこと。
- Playwright（Chromium）によるヘッドレスブラウザ操作で、以下を実機相当で確認:
  - 初期画面の表示、部位カードのクリックによる詳細パネル表示
  - 装着中の部位の取り外し → インベントリへの移動、接続容量表示の更新
  - インベントリの部位の装着（容量不足時はボタンが無効化され、理由が表示される）
  - 戦闘画面の速度切り替え（一時停止/1x/2x/4x）が実際に反映されること
  - デバッグパネルからの部位付与・敵の即時撃破・次フェーズへの進行
  - ドロップ画面での候補比較（現在装着中の同種部位との数値比較）→ 装着 or 保管
  - 全8戦を通しでプレイし、最終ボス撃破による勝利画面・最終ビルド表示・ランリセットまで到達
  - ブラウザコンソールにエラーが出力されないこと
- `scripts/simulate.ts` による自動プレイシミュレーション（部位のスコアリングによる簡易AIが
  ドロップ選択・装着を行い、40ラン×最大8戦を自動実行）で、通常戦12〜17秒・強敵戦17秒前後・
  中ボス17秒前後・最終ボス13秒前後、1ラン平均約60秒（自動戦闘時間のみの合計。準備/ドロップ
  画面の操作時間を含めれば実プレイで5〜10分に収まる想定）、簡易AIでの勝率は約23%という
  結果を確認（人間が能動的にシナジーを狙って構築すればより高い勝率が期待できます）。

## 現在の部位・敵・シナジー一覧

### 部位（28種）

- **初期部位**: 弱い腕（腕・触手／無属性）
- **昆虫** (8種): 鎌腕・毒針腕・蜘蛛脚・複眼・毒腺・糸吐き口・甲殻・女王の腹部
- **ゴーレム** (8種): 岩石腕・巨大拳・石の脚・水晶眼・魔力炉・岩石外殻・反射装甲・古代核
- **ドラゴン** (8種): 竜爪・火炎頭・竜翼・竜の心臓・竜鱗・灼熱腺・竜尾・双頭
- **特殊部位** (4種): 巨大肉塊・増殖細胞・多腕核・百足の心臓（いずれも接続容量/コストに影響）

### 敵

- **通常敵**: 毒蜘蛛・鎌蟲（昆虫）／小型ゴーレム・水晶ゴーレム（ゴーレム）／
  火竜の幼体・翼竜（ドラゴン）
- **強敵**: 昆虫女王・巨像ゴーレム・双頭竜
- **中ボス**: 強敵からランダムに1体を強化して使用
- **最終ボス**: 大キメラ（複数種族の攻撃パターンを持つ）
- 敵は戦闘番号が進むほどHP・攻撃力がスケーリング（種族ごとの立ち回りは、昆虫=手数・毒・回避、
  ゴーレム=防御・低速・高威力、ドラゴン=炎上・高火力として差別化）

### シナジー

- 部位数シナジー: 腕・触手(4/6/10)、頭・口・目(3/5)、心臓・臓器(3/5)、脚・翼(4/8)、皮膚・外殻(3/5)
- 種族シナジー: 昆虫(3/6)、ゴーレム(3/6)、ドラゴン(3/6)
- 詳細な数値・効果は `src/data/synergies.ts` を参照してください。

## 追加改善（プレイフィール向上パッチ）

初回MVP完成後、実プレイで感じた「作業感」「緊張感の無さ」「スマホで遊びにくい」を
低コストで改善するための追加パッチを実施しました。大規模なシステム変更は行わず、
既存のデータ駆動アーキテクチャの上に乗せる形で実装しています。

- **スマホ縦画面レスポンシブ対応**: 640px以下でレイアウトを自動的にコンパクト化。
  戦闘画面はプレイヤー・敵を横並びのまま維持しつつフォント/余白/カードサイズを縮小し、
  自キャラ・敵・HP・状態異常・部位の発動状況・操作(速度切替)が1画面に収まるようにしました。
  デバッグパネルもスマホでは全幅オーバーレイに切り替わり、他のボタンと重ならないようにしています。
  PC表示（640px超）は既存スタイルのまま変更していません。
- **初回チュートリアル**: 起動時に短い説明モーダル（4行）を表示。戦闘準備画面右上の
  「❓遊び方」からいつでも再表示できます。長文説明ではなく、部位カードやシナジーパネル、
  各種ステータスのツールチップ（`title`属性）で都度理解できる設計を維持しています。
- **クリティカル(会心)システムを追加**: 頭・口・目タイプの部位を装着数に応じて
  会心率+5%/個（最大65%、会心倍率1.75倍）が自動的に付与されます（`src/engine/modifiers.ts`の
  `CRIT_CHANCE_PER_HEAD`等で調整可）。閾値シナジーではなく連続スケーリングにしたことで、
  「頭を追加するかどうか」が常に悩みどころになります。レア部位「双頭」は会心倍率にも
  ボーナスを持ちます。
- **難易度曲線の見直し**: 敵のスケーリング係数を引き上げ、強敵・中ボス・最終ボスの
  基礎数値を強化しました。序盤(1-2戦)は変更せず、強敵(3戦目)からは装備が薄いと
  普通に負ける水準、最終ボスはビルドを練らないとまず勝てない水準を狙っています。
  `scripts/simulate.ts` の簡易AIで検証したところ、勝率は0%→約5%まで低下（＝適度に
  歯ごたえのある難易度になったことを確認）。人間の熟練プレイヤーはシナジー閾値を
  意図的に狙うことでこれより高い勝率を出せる設計です。

## 未解決の不具合

- 現時点で把握している既知のクラッシュ・機能不全はありません
  （型チェック・lint・自動プレイテストはすべて通過）。
- ただし数値バランスは簡易AIによるシミュレーションでの検証にとどまっており、
  人間のプレイでは未検証の極端な組み合わせ（非常に高い装着数など）で
  想定外のバランスになる可能性があります。

## 仮置きした数値や仕様

- **戦闘勝利後の少量HP回復（最大HPの35%）**: 心臓・臓器パーツによる戦闘中回復とは別に、
  8連戦を現実的に成立させるための救済措置として追加しました（仕様書に明記はありません）。
  `src/engine/run.ts` の `POST_VICTORY_RECOVERY_PCT` で調整可能です。
- **戦闘中のプレイヤーHPはラン全体で持ち越し**（毎回全回復はしない）という前提で設計しています。
- 部位・敵の攻撃力/HP/間隔などの数値は、`scripts/simulate.ts` によるシミュレーションで
  「通常戦とボス戦で難易度に差がある」「1ランが極端に長すぎない」ことを確認した上での
  仮の値です。正式な数値ではなく、実装後の調整を前提としています。
- 毒・炎上の判定間隔は1秒固定としました（仕様に間隔の指定はありません）。
- 状態異常（毒・炎上）は防御力・被ダメージ軽減率を無視して直接HPに作用する仕様としました。
- 炎上の重複は「ダメージ量とダメージ持続時間の両方が増加する」仕様としました
  （仕様書は「ダメージまたは効果時間が増加する」なので、両方増加はやや強めの解釈です）。
- 初期接続容量は仕様書の10ではなく12としています（バランス調整の結果）。
- ドロップのレアリティ抽選テーブル（通常/強敵/中ボス/最終ボス）は仮の重み付けです。
- 敵の「スケーリング係数」（戦闘番号に応じたHP/攻撃力の伸び率）は仮の一次関数です。
- 会心率は「頭・口・目1個につき+5%（最大65%）」、会心倍率は基礎1.75倍という仮の値です。
  頭が多いほど強くなる一方で腕・心臓・脚・皮膚と装着枠を奪い合うため、選択の悩みどころとして
  機能することを狙っています。

## 次に改善すべき点

- 人間プレイヤーによる実プレイテストを重ね、`scripts/simulate.ts` の簡易AIでは拾えない
  「意図的にシナジー閾値を狙う」プレイのバランスを検証・調整する。
- 部位ごとの数値バランス（特にレア部位の強さ、特殊部位の組み合わせ数値）をより精緻に調整する。
- 状態異常のスタック仕様（毒の増加ペースと減衰ペースの関係、炎上の重複ルール）を
  実プレイのフィードバックを踏まえて再検討する。
- ドロップ演出やパッシブ発動時の視覚フィードバック（現状はログとクールダウンバーのみ）の強化。
- モバイル対応、画像・アニメーション、BGM/SEなど「今回実装しないもの」として明示された要素は
  引き続き対象外。
